# Implementation Plan: Supervisor Portal (R2-CR-8)

**Branch**: `014-supervisor-portal` | **Date**: 2026-06-11 | **Spec**: `specs/014-supervisor-portal/spec.md`

---

## Summary

Wire the existing supervisor frontend scaffold (both scenarios) to real HTTP endpoints, and fill in the two missing backend gaps: a `SupervisorHandler` exposing audit logs and ZK-pointer verification (Scenario B), and a full `OversightHandler` + `OversightService` for the AML/CFT disclosure flow in Scenario A (where it is absent). Scenario B's disclosure endpoints already exist at `/api/v2/oversight/*`; the frontend simply needs to call them instead of the mock.

---

## Technical Context

**Language/Version**: Go 1.26+ (backend), TypeScript / React 18 (frontend)  
**Primary Dependencies**: Fiber v2 (HTTP), GORM + Postgres (persistence), Keycloak OIDC (auth), Zustand (frontend state), TanStack Query (data fetching), shadcn/ui components  
**Storage**: Postgres — existing `audit_log` table (both scenarios); new `disclosure_requests` + `disclosure_signatures` tables (Scenario A only); existing tables in Scenario B  
**Testing**: `go test` (backend unit), Playwright (frontend E2E)  
**Target Platform**: Docker Compose local + LACNet spoke networks  
**Project Type**: Web application (Go API Gateway + React frontend per scenario)  
**Performance Goals**: Audit log query < 500ms p95; ZK pointer verify < 200ms p95  
**Constraints**: No mock data in production paths; sensitive payloads in-memory only (FR-SUP-008); max 100 log entries per page  
**Scale/Scope**: 2 scenarios × (1 backend service + 1 frontend app) = 4 implementation tracks

## Implementation Phases

### Phase 1 — Backend: SupervisorHandler + Audit Logs (both scenarios)

**Goal**: `GET /api/v1/compliance/audit/logs` returns real data for `ROLE_SUPERVISOR` in both scenarios.

**Test-first step**:
1. Write `supervisor_handler_test.go` in **both** scenarios' api-gateway. Test: `TestSupervisorHandler_GetAuditLogs_RequiresSupervisorRole` (assert 403 for governance token) and `TestSupervisorHandler_GetAuditLogs_Success` (assert 200 with log array for supervisor token). Tests must fail before step 2.

**Implementation steps**:
2. Add `RequireSupervisorRole()` to `middleware/require_role.go` in **both** scenarios:
   ```go
   func RequireSupervisorRole() fiber.Handler {
       return RequireRole("ROLE_SUPERVISOR")
   }
   ```
3. Create `handlers/supervisor_handler.go` in **both** scenarios:
   - `SupervisorHandler` struct with a `compliance ComplianceAuditLister` interface field
   - `ComplianceAuditLister` interface: single method `GetAuditLogs(ctx, category, severity, fromDate, toDate string, page, limit int) ([]AuditRecord, error)` — satisfied by the existing `ComplianceGRPCAdapter`
   - `GetAuditLogs` handler: parse query params, call adapter, return JSON with `logs`, `page`, `limit`, `total`
4. Add `SupervisorHandler *handlers.SupervisorHandler` to the `Dependencies` struct in `router.go` for **both** scenarios.
5. Register route in both routers:
   ```go
   supervisorGroup := app.Group("/api/v1/compliance",
       middleware.RequireCookieAuth(deps.AuthProvider),
       middleware.RequireSupervisorRole(),
   )
   supervisorGroup.Get("/audit/logs", deps.SupervisorHandler.GetAuditLogs)
   ```
6. Wire `SupervisorHandler` in `app.go` for **both** scenarios, injecting the existing `complianceAdapter`.

**Verification**: Run `go test ./internal/http/handlers/... -run TestSupervisorHandler`. Both tests must pass.

### Phase 2 — Backend: ZK Pointer Verify (Scenario B only)

**Goal**: `GET /api/v1/compliance/zk-pointer/verify` returns ZK-pointer state for `ROLE_SUPERVISOR`.

**Critical pre-condition** (from research D-02): `ZKComplianceGate` is never instantiated in `app.go` today. `SwapGates.ComplianceGate` is nil at runtime. This phase must instantiate the gate.

**Test-first step**:
1. Write `TestSupervisorHandler_VerifyZKPointer_Valid`, `_NotFound`, `_Expired`, and `_MissingParams` in `supervisor_handler_test.go` (Scenario B). Tests must fail before step 2.

**Implementation steps**:
2. Add `VerifyZKPointer` method to `scenario-b` `SupervisorHandler`:
   - New interface field: `zkGate ZKPointerVerifier` with method `ValidateZKPointer(ctx, bankID, txRef, commitmentHash string) error`
   - Handler reads `bank_id` and `commitment_hash` from query; validates required; calls `zkGate.ValidateZKPointer`
   - On nil error: query DB directly for `pointer_id` and `expires_at` to build response (or extend `ZKComplianceGate` to return the record, not just error)
   - Response: `ZKPointerVerification` JSON (see contracts/supervisor-api.md)
3. In `scenario-b/backend/services/api-gateway/internal/app/app.go`: instantiate `ZKComplianceGate`:
   ```go
   zkGate := services.NewZKComplianceGate(db)
   ```
   Inject into `SupervisorHandler` constructor (new parameter alongside `complianceAdapter`).
4. Register route:
   ```go
   supervisorGroup.Get("/zk-pointer/verify", deps.SupervisorHandler.VerifyZKPointer)
   ```

**Note on `ZKComplianceGate.ValidateZKPointer` return value**: the current method only returns `error`. To return `pointer_id` and `expires_at`, either (a) add a `GetZKPointerRecord(ctx, bankID, commitmentHash) (*zkPointerRecord, error)` method to the gate, or (b) do a second DB query in the handler. Option (a) is cleaner — add the method to `ZKComplianceGate` as part of this phase.

**Verification**: `go test ./internal/http/handlers/... -run TestSupervisorHandler_VerifyZKPointer`

### Phase 4 — Frontend: Base HTTP Client + Auth/Network/Governance Wiring (both scenarios)

**Goal**: Replace `mockDb` calls in `auth.api.ts`, `network.api.ts`, `governance.api.ts`, `stability.api.ts` with real HTTP. Zero mock calls remaining in those four modules.

**Steps** (identical for both scenarios' supervisor apps):

1. Create `src/services/api/client.ts`:
   ```typescript
   const BASE = import.meta.env.VITE_API_BASE_URL ?? "";

   export class ApiError extends Error {
     constructor(public status: number, message: string) { super(message); }
   }

   export async function apiFetch<T>(path: string, init?: RequestInit): Promise<T> {
     const res = await fetch(`${BASE}${path}`, {
       ...init,
       credentials: "include",
       headers: {
         "Content-Type": "application/json",
         "X-Correlation-Id": crypto.randomUUID(),
         ...init?.headers,
       },
     });
     if (!res.ok) {
       const body = await res.json().catch(() => ({}));
       throw new ApiError(res.status, body.error ?? res.statusText);
     }
     return res.json() as Promise<T>;
   }
   ```

2. Replace `auth.api.ts`: call `POST /api/v1/auth/login`, `GET /api/v1/auth/me`, `POST /api/v1/auth/logout`.
3. Replace `network.api.ts`: call `GET /api/v1/compliance/participants` (network overview is derived from participant count — keep the same shape or call the governance overview endpoint if one exists).
4. Replace `governance.api.ts`: call `GET /api/v1/compliance/participants`.
5. Replace `stability.api.ts`: call `GET /api/v1/governance/parameters` or the appropriate pool status endpoint (verify exact route in the router during implementation).
6. Delete `mockDb.ts` imports from all four modules above. Keep `mock-db.ts` file intact (remove only the imports in the api modules) until Phase 5 clears the last usage.
