## Conventions

| Symbol | Meaning |
|--------|---------|
| **required** | Must be set; no functional default value |
| `default: X` | Default value applied if not set |
| `auto` | Populated automatically by the system (do not edit manually) |
| `⚠️ secret` | Never version-control; use a secret manager in production |

## Backend per entity (`.env.infra.<entity>`)

File: `scenario-a/backend/config/.env.infra.<entity>`  
Template: `scenario-a/backend/config/.env.infra.<entity>.example`

> These files are generated automatically by the Keycloak initialization script during `make deploy.up-infra`. Fields marked `auto` are populated by the Keycloak init; the rest must be present in the `.example` before the first run.

### Keycloak (per entity)

| Variable | Example (bank-a) | Type | Description |
|----------|-----------------|------|-------------|
| `KC_BASE_PATH` | `http://localhost:8081` | URL | Keycloak base URL |
| `KC_REALM` | `bank-a` | string | Dedicated realm for the entity |
| `KC_CLIENT_ID` | `bank-a-client` | string | OIDC client ID |
| `KC_CLIENT_SECRET` | `bank-a-local-secret` | string ⚠️ `auto` | Client secret generated by Keycloak |

### PostgreSQL (per entity)

| Variable | Example (bank-a) | Type | Description |
|----------|-----------------|------|-------------|
| `DB_NAME` | `cbweb3_bank_a` | string | Entity database name |
| `DATABASE_URL` | `postgres://default:default@cbweb3-postgres:5432/cbweb3_bank_a?sslmode=disable` | DSN | Full connection string |

### Redis (per-entity isolation)

| Variable | Default (bank-a) | Type | Description |
|----------|-----------------|------|-------------|
| `REDIS_DB` | `0` | int | Redis database (0–5, one per entity) |

Default mapping: bank-a=0, bank-b=1, central-bank-a=2, bank-c=3, bank-d=4, central-bank-b=5.

### PKI

| Variable | Example | Type | Description |
|----------|---------|------|-------------|
| `CA_CERT_FILE` | `/workspace/backend/config/pki/bank-a-ca.crt` | path | Entity CA certificate |
| `CA_KEY_FILE` | `/workspace/backend/config/pki/bank-a-ca.key` | path ⚠️ | CA private key |

> In production: replace with Docker Secrets variables (`/run/secrets/ca.crt`, `/run/secrets/ca.key`).

### Blockchain (Besu)

| Variable | Example (bank-a) | Type | Description |
|----------|-----------------|------|-------------|
| `BLOCKCHAIN_CLIENT` | `besu` | enum | Blockchain client (`besu`) |
| `BESU_RPC_URL` | `http://cbweb3-spoke-a-besu.bank-a:8545` | URL | Entity's Besu node RPC URL |
| `BESU_CHAIN_ID` | `1338` | int | Chain ID (1338=spoke-a, 1339=spoke-b) |

### Contract addresses (populated by `make contracts.sync-addresses`)

| Variable | Type | Description |
|----------|------|-------------|
| `PARTICIPANT_REGISTRY_ADDRESS` | address `auto` | Deployed IdentityRegistry |
| `TOKEN_ADDRESS` | address `auto` | tCeBM (ERC-20 CBDC) |
| `HTLC_ADDRESS` | address `auto` | HashTimeLockedContract |
| `FX_AGREEMENT_ADDRESS` | address `auto` | FXAgreement |
| `SPOKE_BRIDGE_ADDRESS` | address `auto` | SpokeBridge |
| `FIAT_TOKEN_ADDRESS` | address `auto` | fCeBM (collateralized fiat) |

### Inter-entity communication

| Variable | Example | Type | Description |
|----------|---------|------|-------------|
| `CENTRAL_BANK_API_URL` | `http://api-gateway-central-bank-a:8080` | URL | Central bank URL (for 3-phase onboarding) |
| `CORS_ALLOW_ORIGINS` | `http://localhost:5173` | list | CORS-allowed origins |
| `BANK_A_FRONTEND_PORT` | `5173` | int | Frontend port (reference) |

### FX Agreement

| Variable | Default | Type | Description |

| `FX_AGREEMENT_HTLC_STRICT` | `false` | bool | Require FX Agreement linked to HTLC lock |

### Relay (HTLC)

| Variable | Default | Type | Description |
|----------|---------|------|-------------|

### Pente (bilateral context)

|----------|---------|------|-------------|
| `PENTE_ENABLED` | `false` | bool | Enable Pente integration |
| `PENTE_BASE_URL` | `http://host.docker.internal:31658` | URL | Paladin/Pente node URL |

## Scenario B — configuration

Scenario B is implemented and carries its own configuration surface, rendered by the
`cbweb3b` provisioning toolkit rather than shared with Scenario A. This document
covers Scenario A only; for Scenario B see:

- [`scenario-b/docs/runbooks/configuration-reference.md`](../../../scenario-b/docs/runbooks/configuration-reference.md) — the variable reference
- [`scenario-b/docs/runbooks/contract-configuration.md`](../../../scenario-b/docs/runbooks/contract-configuration.md) — contract addresses and wiring
- [`scenario-b/provisioning/`](../../../scenario-b/provisioning/) — the compose templates and manifest schema the toolkit renders from

Scenario isolation is a constitutional rule of this repository: no variable
documented here is read by a Scenario B service.
